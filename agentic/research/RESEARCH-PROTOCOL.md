# Research Protocol

## Gerarchia fonti

1.  Documentazione ufficiale Android/Google/Play e specifiche/API.
2.  Sample e repository ufficiali.
3.  Issue tracker/release notes ufficiali.
4.  Repository open source e implementazioni verificabili.
5.  Articoli tecnici di autori/aziende identificabili.
6.  Forum/community: solo come indizio da verificare.

## Scheda minima per ogni finding

-   domanda;
-   risposta sintetica;
-   stato: verified / partial / uncertain / obsolete;
-   fonte;
-   data pubblicazione/aggiornamento se disponibile;
-   data di verifica;
-   versione SDK/API/policy;
-   evidenza essenziale;
-   implicazione per BAuto;
-   limiti;
-   controevidenze;
-   follow-up / PoC.

## Regole

-   Non usare un singolo articolo secondario come prova di una
    capability.
-   Cercare controevidenze per le capability critiche.
-   Distinguere Android Auto da Android Automotive OS.
-   Registrare informazioni obsolete quando spiegano differenze tra
    esempi vecchi e API correnti.
-   Conservare link e riferimenti, non copie integrali di contenuti
    protetti.
-   Le conclusioni devono essere riproducibili.
